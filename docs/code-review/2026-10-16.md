# Code review — meraki-info, 2026-10-16

Branch `code-review`, started from `overnight-docs` (`01460a3`), which started from tag `pre-docs`
(`93a0c9e`). Reviewer: Claude (overnight session). Nothing was run against the live Meraki API;
every check below is offline (unit tests, `httptest` servers, argument parsing).

## Summary

A small, readable Go CLI with sound basics: one dependency, read-only GETs, retry with backoff,
wrapped errors, and tests that never leave the machine. The real problems are in the **`-all`
paths in `main.go`** and in **error reporting on output**:

- Three of the four consolidated reports ignored `-org` (fixed).
- CSV output and file closes could fail silently, leaving a truncated file while the command
  reported success (fixed).
- `-all -output FILE` writes every network to the same file, so only the last network survives
  (not fixed: needs a decision on file naming — Question 1).
- The `access` command printed usage examples for a binary and flags that do not exist, and the
  `make access` targets could never work (fixed).
- The PowerShell `make` helper errored every time it was loaded (fixed).

6 issues fixed, 15 found and not fixed, 9 questions. Build, vet and all tests pass before and
after; `golangci-lint` (default config) went from 22 to 19 `errcheck` findings.

## Fixed

1. **Consolidated `licenses`, `down` and `alerting` ignored `-org`.**
   `main.go:346`, `main.go:419`, `main.go:481`; new helper `organizationsToReport` at
   `main.go:862`.
   *What:* `meraki-info -org X down` (no `-network`, so `-all` is implied, output to stdout)
   walked every organization the key can see, not just X. `route-tables` already honored `-org`,
   and the `-all` help text says "If -org specified, get info for all networks in that
   organization".
   *Why:* the most common invocation returned other organizations' devices and licenses, and made
   one API call per network of every organization.
   *How verified:* new `TestOrganizationsToReport` in `main_test.go` (no `-org` → all; `-org 2` →
   only 2; unknown → none). The consolidated functions themselves cannot be unit-tested from
   package `main`, because `meraki.Client`'s `baseURL` is unexported and cannot be pointed at a
   test server from outside the package; the fix is one line per function that applies the
   tested helper.

2. **CSV write errors were dropped.** `internal/output/writer.go:897`, `:943`, `:992`, `:1047`.
   *What:* each CSV writer did `defer csvWriter.Flush()` and never checked `csvWriter.Error()`.
   `csv.Writer` buffers 4 KB, so a typical report only reaches the file at that final flush.
   *Why:* on a full disk or a closed pipe the CSV came out empty or truncated and the command
   still logged success and exited 0.
   *How verified:* test written first: `TestCSVWriter_WriteTo_ReportsWriteError`
   (`internal/output/writer_test.go`) uses an `io.Writer` that always fails; all four subtests
   (routes, routes with network, licenses, devices) **failed before** the fix and pass after.

3. **File close errors were dropped.** `internal/output/writer.go:246`, `:530`, `:573`, `:812`
   (`WriteToFile` for text, JSON, XML, CSV).
   *What:* `defer file.Close()` discarded the close error.
   *Why:* on network filesystems a failed close can mean the data never landed; it is now
   returned as `failed to close file: …`.
   *How verified:* existing `WriteToFile` tests pass; `go vet` clean; `errcheck` no longer flags
   these lines. No new test: forcing `Close` to fail on a regular file is not practical on
   macOS/Linux without fault injection, which this code has no seam for.

4. **`access` printed wrong usage examples.** `main.go:798`–`827`.
   *What:* the examples named `./meraki-routes-backup` (the project's old name), used an
   `--access` flag that does not exist, and omitted the command, so every example failed if
   copied. The "-all" example also promised "separate files".
   *Why:* the first thing a new user runs printed commands that do not work.
   *How verified:* each new example form (`--org X route-tables`, `--network N route-tables`,
   `--all route-tables`, `--org X access`) was run through `parseConfigWithValidation` in a
   temporary test (deleted afterwards) — all accepted.

5. **`make access` / `.\make.ps1 access` could never work.** `Makefile:98`, `:100`;
   `make.ps1:310`, `:312`.
   *What:* they ran `meraki-info access --apikey KEY`. Go's flag parser stops at the first
   non-flag, so the CLI saw three commands and exited with "only one command is allowed"
   (reproduced with the built binary; it fails during parsing, before any API call).
   *Why:* the documented target was dead. The fix drops `--apikey` entirely: both targets already
   require `MERAKI_APIKEY`, which `meraki-info` reads itself, and the key no longer appears in the
   process list.
   *How verified:* `make -n access` shows `./meraki-info access`; the existing config test
   "valid access command config" covers that exact form with the key from the environment.

6. **`PowerShell-Make-Function.ps1` errored on every use.** Last line removed.
   *What:* `Export-ModuleMember -Function make` only works inside a module; the file's own
   instructions say to dot-source it or paste it into `$PROFILE`, which produced
   "The Export-ModuleMember cmdlet can only be called from inside a module" every time.
   *How verified:* `pwsh`: dot-sourcing now leaves `$Error.Count` at 0 and `make` is defined
   (before: 1 error, function still defined).

## Found, not fixed

1. **`-all -output FILE` keeps only the last network.** `main.go:887`, `:927`, `:1019`,
   `:1085` (`infoOrganizationNetwork*`). Each network is written to the same `cfg.OutputFile`,
   each overwriting the last. The per-network timestamped names this was built for were removed
   in `f376ff6` ("Remove --alerting --output default"). Not fixed: choosing a file-name scheme,
   or appending, or switching to consolidated output, changes behaviour and output files.
   → Question 1.
2. **`licenses -all -output FILE` re-fetches the same org-wide list once per network** and
   writes it N times (`main.go:927` → `infoSingleNetworkLicenses`, which ignores the network,
   `main.go:190`). Wasted API calls. Falls out of whatever Question 1 decides.
3. **Consolidated XML/CSV for licenses and devices are JSON.** `internal/output/writer.go:606` (XML)
   and `:845` (CSV). `-format csv down` (the default `-all` path) prints JSON. Not fixed:
   designing the XML/CSV columns is a data-format decision. → Question 2.
4. **`down` may never find anything live.** `internal/meraki/client.go:1524`. It reads `status`
   from `GET /networks/{id}/devices`; `alerting` (`:1557`) deliberately joins
   `GET /organizations/{id}/devices/statuses` instead, with a comment that the basic status
   "might be empty". If the network devices endpoint does not return `status`, `down` always
   reports zero devices. Not verifiable without the live API. → Question 3.
5. **`down` includes `alerting` devices.** `isDeviceDown`, `client.go:1681`. Possibly intended,
   but it means `down` and `alerting` overlap. → Question 4.
6. **Text title says "Meraki Down Devices" for alerting output** (per-network, i.e. with
   `-network`). `writer.go:396`. Changing printed text was left alone in case something parses
   it. → Question 4.
7. **No pagination.** Every list endpoint (`/organizations/{id}/networks`,
   `/devices/statuses`, `/licenses`, `/networks/{id}/devices`) is read as one page. Meraki
   paginates these with `Link` headers; large organizations will be silently truncated.
   → Question 5.
8. **`Retry-After` ignored on 429.** `makeRequest`, `client.go:408`; waits are fixed 1s, 1s, 2s.
   Under real rate limiting the three retries can all land inside the limit window. Suggested
   follow-up, low risk, but changes timing behaviour.
9. **Alerting `-all` calls the org-wide statuses endpoint once per network**
   (`client.go:1565` via `GetAlertingDevices` per network). N+1 calls; contributes to rate
   limiting on big organizations.
10. **Consolidated route records put the org *ID* in `organization` when `-org` is given, and
    the org *name* otherwise.** `main.go:612` (the comment there acknowledges it). Inconsistent
    output column. → Question 6.
11. **Empty consolidated `licenses`/`down`/`alerting` encode as JSON `null`, routes as `[]`.**
    `main.go:348`, `:421`, `:483` declare nil slices. A `jq '.[]'` consumer errors on `null`.
    Format change, so left alone. → Question 6.
12. **`Fixed IP: <nil>` in text and CSV** for routes without fixed assignments
    (`writer.go:312`, `:344`, `:888`, `:934`, `%v` of a nil interface). Cosmetic, format change.
13. **CSV formula injection.** Device names, notes, addresses and network names come from the
    dashboard and are written to CSV unescaped; a value starting with `=`, `+`, `-` or `@` is
    executed as a formula when the CSV is opened in Excel. Risk is limited to dashboard admins
    planting values, but README and REQUIREMENTS.md advertise spreadsheet/Excel use. → Question 7.
14. **Dead code.** `NewClientWithOAuth2` (`client.go:318`, and with it the only external
    dependency `golang.org/x/oauth2`), `GetAllNetworkLicenses` (`:1424`), `GetAllNetworkDevices`
    (`:1639`), the `NetworkLicenses`/`NetworkDevices` types, the unreachable tail of
    `makeRequest`, and the `OutputFile == ""` checks inside the `infoOrganizationNetwork*` loops
    (callers already guarantee a file). README advertised OAuth2 until the docs pass.
    → Question 8.
15. **Duplication in `main.go`.** Each command has four near-identical functions (single,
    consolidated, per-org, all-orgs): about 600 lines that differ only in the fetch call and
    record type. Duplication like this is how `-org` handling drifted between commands (Fixed 1).
    A refactor is worth it but is not surgical. → Question 9.

Also noted, minor: an unsupported `-format` or `-loglevel` value silently falls back to text /
error instead of failing; `WriteToFile` creates (truncates) the file before checking the data
type, so an unsupported type leaves an empty file; when `access` is given an unknown `-org`
name, `main` fails in `ResolveOrganizationID` before `showAccessInformation`'s friendlier
"available organizations" listing can run; `Route.Enabled` for switch-stack static routes is
`preferOverOspfRoutesEnabled` (`client.go:1096`), a documented stand-in that can mislabel routes.

## Questions for Kent

1. **What should `-all -output FILE` produce?** (a) bring back one timestamped file per network,
   (b) one consolidated file (same as stdout output, just to a file), or (c) leave it.
   *Recommendation: (b)* — it is a few lines (route the file case through the existing
   consolidated functions), keeps the network/org columns, and avoids the overwrite entirely.
2. **Consolidated `-format xml|csv` for licenses/devices currently emits JSON.** Add real XML/CSV
   layouts (org + network columns first, then the per-type columns), or reject those
   combinations with an error? *Recommendation:* real CSV (it is what spreadsheets want) and an
   error for XML until someone needs it.
3. **Does `down` work on a live organization?** Please run
   `meraki-info -org <org> -network <a network with a known offline device> -format json down`
   once. If it returns nothing, *recommendation:* reuse the device-statuses join that `alerting`
   already uses.
4. **Is "alerting counts as down" intended?** If yes, I would retitle the per-network text
   header from "Meraki Down Devices" to "Meraki Devices" (as the consolidated one already is).
   If no, drop `alerting` from `isDeviceDown`. *Recommendation:* keep the overlap (alerting is
   operationally interesting), fix the title.
5. **Add pagination?** *Recommendation: yes* — follow the `Link: rel=next` header in
   `makeRequest`'s callers for the four list endpoints; without it large organizations are
   silently incomplete.
6. **Consolidated output consistency:** use the org *name* in route records' `organization` (and
   add `organization_id`, as devices/licenses have), and emit `[]` instead of `null` for empty
   results? *Recommendation: yes to both*; both are output-format changes, hence asking.
7. **Guard CSV against formula injection** (prefix a `'` to cells starting with `= + - @`)?
   *Recommendation: yes*, low cost; but it changes cell values, hence asking.
8. **Remove the unused OAuth2 constructor (and the `golang.org/x/oauth2` dependency) and the
   unused `GetAllNetwork*` functions?** *Recommendation: yes*, unless OAuth2 is planned soon.
9. **Refactor `main.go`'s per-command duplication** into one generic path (Go generics over the
   record type)? *Recommendation: yes, after* Questions 1 and 2 are answered, since they change
   the same code.
